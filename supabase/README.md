# إعداد تكامل التتبع والطلبات المتروكة

ملفات SQL لا تُطبّق تلقائيًا عند نشر التطبيق إلى Vercel. افتح Supabase **SQL Editor** وطبّق الترحيلات يدويًا، بالترتيب:

- لقاعدة حالية أُعدت سابقًا: `migrations/0001_place_order.sql` و`migrations/0002_pixels_and_abandoned_checkouts.sql` إذا لم يكونا مطبقين، ثم `migrations/0003_product_admin_fields.sql` و`migrations/0004_admin_rls_helper.sql`.
- لقاعدة جديدة: نفّذ `schema.sql` ثم `migrations/0001_place_order.sql`. يتضمن `schema.sql` الجداول والسياسات وحقول المنتجات ودالة المدير الحالية.

الترحيلان `0003` و`0004` آمنان لإعادة التشغيل: الأول يضيف أعمدة المنتجات إن لم تكن موجودة، والثاني يعيد تعريف دالة التحقق من المدير لتعمل بأمان مع RLS. لا تنفّذ `schema.sql` كاملًا فوق قاعدة قائمة بدل ملفات الترحيل.

بعدها، تأكد أن حساب الإدارة المسجل في Supabase Auth له صف مطابق في `public.profiles` وقيمة `role = 'admin'`. الحساب التجريبي المحلي ليس حساب Supabase ولا يمنح صلاحية الكتابة إلى قاعدة البيانات.

إذا كانت منتجات مخصصة محفوظة في متصفح لوحة الإدارة فقط، افتح تبويب **المنتجات** بعد الترحيلات واستخدم زر **حفظ المنتجات المحلية في المتجر**. يعرض الزر عدد المنتجات المخصصة المرشحة، يستبعد بيانات seed، ويتخطى أي slug موجود بدل استبداله. لا تحذف بيانات المتصفح قبل اكتمال الاستيراد والتحقق من ظهور المنتجات في المتجر.

بعد الترحيل، سجّل الدخول إلى لوحة الإدارة وافتح **الإعدادات والربط ← البيكسل الإعلاني** لإدخال معرّفات Meta الستة وTikTok الأربعة. تُترك الحقول فارغة ومعطّلة افتراضيًا. لا تُحمّل البرامج النصية ولا تُرسل أحداثها قبل موافقة الزائر على التسويق؛ أحداث بدء الدفع ليست أحداث شراء، ولا تُرسل معلومات الاتصال إلى منصات الإعلانات.

تُحفظ مسودات النماذج غير المكتملة لمدة 30 يومًا. بيانات الاتصال اختيارية ولا تُحفظ إلا بعد موافقة صريحة داخل النموذج. تعرض لوحة **الطلبات المتروكة** هذه المسودات منفصلة عن الطلبات الحقيقية غير المسلّمة.
